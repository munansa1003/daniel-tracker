# 애플워치 운동 자동 기록 — 단축어 조립 가이드

폰에서 이 문서를 그대로 따라 만들면 됩니다. 총 3개(자동화 A·B + 원탭 버튼)를 만들지만,
**단축어 본체는 하나**고 나머지 둘은 그 단축어를 부르는 트리거입니다.

> **스키마 단일 출처**: 요청 형식(필드명·날짜 형식·화이트리스트)의 원본 정의는
> `api/_lib/import-rules.js`입니다. 이 문서는 그 정의를 옮겨 적은 것이며, 어긋나면
> 계약 테스트(`src/__tests__/health-import.test.js` §7)가 잡습니다.

## 0. 준비물 — 실값 (Phase 4 머지 후 치환)

| 항목 | 값 |
|---|---|
| 엔드포인트 URL | `⟨배포 URL⟩/api/health-import` ← **머지 후 실값으로 치환** |
| 인증 헤더 이름 | `X-Import-Token` |
| 인증 헤더 값 | `⟨IMPORT_TOKEN 비밀값⟩` ← Vercel에 설정한 것과 동일하게 |
| HTTP 메서드 | `POST` |
| 본문 형식 | JSON (아래 1.3) |

### 0.1 서버 환경변수 3종 (Vercel → Settings → Environment Variables)

셋 다 설정해야 검문소가 열립니다. **하나라도 없으면 엔드포인트는 503으로 잠김**(실수 배포 방지).

| 변수 | 값 | 설명 |
|---|---|---|
| `IMPORT_TOKEN` | 긴 무작위 문자열 (예: `openssl rand -hex 24` 결과) | 단축어의 `X-Import-Token` 헤더와 대조 |
| `IMPORT_UID` | 본인 Firebase uid | 어느 사용자의 사서함에 넣을지 |
| `IMPORT_CUTOVER_DATE` | 예: `2026-08-07` (자동화 시작일) | 이 날짜 이전에 **시작된** 운동은 거부 — 과거 수동 기록과 이중 계상 차단 |

> 본인 uid 확인법: 앱 로그인 상태에서 브라우저 개발자도구 콘솔에
> `localStorage.getItem("dt_currentUser")` 입력.

설정 후 **재배포**해야 반영됩니다.

## 1. 단축어 본체 만들기 — 이름: "운동 자동 기록"

단축어 앱 → `+` 새 단축어 → 아래 동작을 순서대로 추가.

### 1.1 건강 샘플 찾기

1. 동작 추가 → **"건강 샘플 찾기"** (Find Health Samples)
   - 유형: **운동** (Workouts)
   - 필터: **시작 날짜**가 **오늘** 인 항목
   - 정렬: **시작 날짜** / **최신 항목 우선**
   - 제한: 켜기 → **10개**
   - (운동 종료 직후 실행돼도 방금 운동이 포함되도록 "오늘 전체"를 매번 보냅니다.
     같은 운동이 반복 전송되지만 **서버가 중복을 무시**하므로 안전 — 그게 설계입니다)

### 1.2 반복(각 운동 → 사전 만들기)

2. **"각 항목 반복"** (Repeat with Each) — 대상: 위의 건강 샘플
3. 반복 블록 **안에** → **"사전"** (Dictionary) 동작 추가. 항목 5개:

   | 키 | 타입 | 값 (마법 변수) |
   |---|---|---|
   | `type` | 텍스트 | `반복 항목` → **운동 유형** (Workout Type) |
   | `start` | 텍스트 | `반복 항목` → **시작 날짜** ⚠️ 아래 1.2.1 형식 필수 |
   | `end` | 텍스트 | `반복 항목` → **종료 날짜** ⚠️ 동일 |
   | `durationMin` | 숫자 | `반복 항목` → **기간(분)** — "분" 단위인지 확인 |
   | `kcal` | 숫자 | `반복 항목` → **활성 에너지** ⚠️ 아래 1.2.2 반올림 필수 |

   그리고 여섯 번째 항목: `device` / 텍스트 / `Apple Watch` (고정 텍스트).

   **⚠️ 1.2.1 날짜 형식 — 반드시 ISO 8601**
   사전에 넣은 `시작 날짜` 변수를 탭 → **날짜 포맷** = **ISO 8601** 선택,
   **"ISO 8601 시간 포함"** 켜기. `종료 날짜`도 동일.
   (결과 예: `2026-08-06T18:20:00+09:00` — 오프셋 없는 값이나 "2026년 8월 6일…" 같은
   로케일 형식이 가면 서버가 400 + "ISO 8601 필요"로 거부합니다)

   **⚠️ 1.2.2 kcal 정수 반올림**
   `활성 에너지`는 소수로 옵니다(예: 445.83). 사전에 넣기 전에
   **"숫자 반올림"** (Round Number) 동작으로 **일의 자리 반올림** 후 그 결과를 사전에 넣으세요.

4. 반복 블록 안 마지막에 → **"변수에 추가"** (Add to Variable): 위 사전을 변수 `workoutList`에 추가.

> **왜 사전(Dictionary)으로 조립하나** — 텍스트 템플릿으로 JSON을 짜면 운동 이름의
> 따옴표·특수문자에서 깨집니다. 사전→JSON 자동 변환은 이스케이프가 항상 안전합니다.

### 1.3 요청 본문 조립 + 전송

5. 반복 블록 **밖**(아래)에 → **"사전"** 동작 하나 더. 항목 3개:

   | 키 | 타입 | 값 |
   |---|---|---|
   | `source` | 텍스트 | `workout-end` ← 자동화 B에서는 이 값만 `evening-backup`으로, 원탭은 `manual-tap` (선택: 셋 다 `workout-end`로 둬도 동작엔 지장 없음 — 로그 구분용) |
   | `sentAt` | 텍스트 | **현재 날짜** 변수 → 날짜 포맷 **ISO 8601**(시간 포함) |
   | `workouts` | 배열 | 변수 `workoutList` |

6. **"URL 콘텐츠 가져오기"** (Get Contents of URL):
   - URL: `⟨배포 URL⟩/api/health-import`
   - 방법: **POST**
   - 헤더: `X-Import-Token` = `⟨IMPORT_TOKEN 비밀값⟩`
   - 본문 요청: **JSON** → 위 5번 사전
7. **"사전 값 가져오기"** (Get Dictionary Value): 키 `message` ← URL 콘텐츠 결과에서
8. **"알림 표시"** (Show Notification): 제목 `Body Plan 자동 기록`, 본문 = 위 `message`
   (예: "2건 추가 · 중복 1 무시 · 근력 1 제외")

## 2. 자동화 A (주력) — 운동 종료 시 자동 실행

1. 단축어 앱 → **자동화** 탭 → `+` → **개인용 자동화**
2. 트리거: **Apple Watch 운동** → **운동을 종료할 때**
3. 동작: **"단축어 실행"** → "운동 자동 기록"
4. 그 앞에 **"대기"** (Wait) **15초** 추가 — 워치→건강 앱 데이터 도착 시간 벌기
5. **"실행 전에 묻기" 끄기** (확인 없이 실행) ← 이걸 꺼야 완전 자동

## 3. 자동화 B (백업) — 매일 21:30

1. 자동화 → `+` → **하루 중 시간대** → **21:30**, 매일
2. 동작: 같은 단축어 "운동 자동 기록" 실행 + "실행 전에 묻기" 끄기
3. (선택) B 전용 사본을 만들어 `source`만 `evening-backup`으로 바꾸면 설정 카드에서
   어느 경로로 들어왔는지 구분됩니다.

낮에 트리거 A가 실패했어도(폰 꺼짐 등) 밤에 오늘 운동 전체가 다시 전송됩니다.
이미 들어간 운동은 전부 "중복 무시"로 끝나므로 아무것도 망가지지 않습니다.

## 4. 원탭 버튼 (3차 보험)

단축어 "운동 자동 기록" → 공유 → **홈 화면에 추가**.
알림이 안 온 것 같을 때 언제든 한 번 탭 — 역시 중복은 서버가 무시합니다.

## 5. 서버가 받아주는 운동 (유산소 화이트리스트)

한국어/영어 어느 쪽으로 와도 인식합니다 (기기 언어 무관):

- 달리기 · Running · Outdoor/Indoor Run → **러닝**으로 저장
- 사이클링 · Cycling · Indoor Cycling · 자전거 → **사이클링**
- 걷기 · Walking → **걷기**
- 축구 · Soccer · Football → **축구**
- 계단 오르기 · Stair Climbing → **계단 오르기**
- 하이킹 · 등산 · Hiking → **하이킹**
- 수영 · Swimming → **수영**

**근력 계열(기능성/전통적 근력 훈련)은 자동 저장하지 않습니다** — 워치가 부위를 몰라
상/하체 통계가 무너지기 때문. 알림의 "근력 N 제외"가 수동 입력 리마인더 역할을 합니다.
그 외 유형(요가 등)은 "대상 외"로 제외되고 서버 로그에 유형명이 남습니다(추후 명단 확장 검토용).

## 6. 값 검증 규칙 (서버 검문소)

| 항목 | 허용 범위 | 벗어나면 |
|---|---|---|
| kcal | 1 ~ 2,000 (정수 반올림) | 거부 (kJ 오염·이상치 차단) |
| durationMin | 1 ~ 600분 | 거부 |
| 시작 날짜 | 컷오버(`IMPORT_CUTOVER_DATE`) 이후 | 이전이면 거부 |
| 날짜 형식 | 오프셋 포함 ISO 8601 | 400 에러 ("ISO 8601 필요") |
| 기록 귀속일 | **시작 시각의 로컬 날짜** (자정 걸친 운동은 시작일) | — |

응답 상태코드: `200` 정상 / `400` 형식 오류 / `401` 토큰 불일치 / `405` POST 외 / `503` 서버 미설정(잠김).

## 7. 반영 확인

전송 후 **앱을 열면** 사서함의 운동이 그 날 기록으로 들어옵니다(수동 입력과 동일 경로 —
유효목표·휴식일 자동 복귀·통계 전부 자동 반영). 가져온 운동에는 ⌚ 배지가 붙고,
일반 기록처럼 **수정·삭제할 수 있으며**, 수정해도 재전송이 덮어쓰지 않습니다(insert-only).
설정 → 데이터 탭 → **"자동 가져오기 (애플워치)"** 카드에서 컷오버 날짜와 최근 수신 5건을
확인할 수 있습니다.

## 8. curl 실전 시뮬레이션 (배포 검증용 — Phase 4)

```bash
URL="⟨배포 URL⟩/api/health-import"
TOKEN="⟨IMPORT_TOKEN 비밀값⟩"

# ① 정상 1건 → {"accepted":1,...,"message":"1건 추가"}
curl -sS -X POST "$URL" -H "X-Import-Token: $TOKEN" -H "Content-Type: application/json" -d '{
  "source":"manual-tap","sentAt":"2026-08-07T19:00:00+09:00",
  "workouts":[{"type":"실외 달리기","start":"2026-08-07T18:20:00+09:00","end":"2026-08-07T18:50:00+09:00","durationMin":30,"kcal":446,"device":"curl"}]}'

# ② 같은 본문 재전송 → {"ignored":1,...} (중복 무시)
#   (①과 동일 명령 반복)

# ③ 근력 → {"filtered":1,...,"message":"0건 추가 · 근력 1 제외"}
curl -sS -X POST "$URL" -H "X-Import-Token: $TOKEN" -H "Content-Type: application/json" -d '{
  "source":"manual-tap","sentAt":"2026-08-07T19:00:00+09:00",
  "workouts":[{"type":"기능성 근력 훈련","start":"2026-08-07T17:00:00+09:00","end":"2026-08-07T17:40:00+09:00","durationMin":40,"kcal":250}]}'

# ④ 토큰 오류 → 401
curl -sS -o /dev/null -w "%{http_code}\n" -X POST "$URL" -H "X-Import-Token: wrong" -H "Content-Type: application/json" -d '{}'
```

> ①·②로 넣은 시험 기록은 앱에서 삭제하면 됩니다(⌚ 배지로 식별). 삭제해도 접수 도장이
> 남아 재전송으로 되살아나지 않습니다.
