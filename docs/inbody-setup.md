# 인바디 체성분 자동 수신 — 최종 구성 (HAE Basic + 단축어)

hae-setup.md(운동)의 자매 문서. 폰 교체·단축어 파손 시 이 문서만으로 재조립할 수 있다.
⚠️ 이 문서의 "첫 실전송 확인 3종"이 체크되기 전까지는 **운영 검증 전 상태**다 — 첫 주에
수신 로그로 확정하고 이 문서를 최종화한다.

## 최종 아키텍처

```
[아침 공복 H20 측정] → InBody 앱 열람(=애플 건강 동기화: 체중·체지방률·제지방체중) → 앱 닫기
  → iOS 자동화 C (InBody 앱이 닫힐 때 · 즉시 실행)
  → 단축어 "Body Plan 체성분 전송"
      ① HAE 건강 지표 내보내기: 체중·체지방률·체질량(=제지방) 3종 · 오늘 · JSON
      ② URL 콘텐츠 가져오기: POST /api/body-import
  → 검문소 /api/body-import (아침 창·소수형·단위·컷오버·샘플 최신 채택 — B1~B9)
  → KV 사서함(import:body-inbox) → 앱 열 때 "완성 대기 초안"으로 착지
  → 사용자는 골격근·점수 2개만 입력 → 확정(잠금) → 이후 도착분은 병합 계층에서 폐기
```

- 타이핑 4개 → 2개. 골격근량·인바디점수는 HealthKit에 항목이 없어 자동화 불가(수동 입력 유지)
- **운동 파이프라인과 완전 분리**: 별도 단축어·별도 서버 함수·별도 사서함/로그 키.
  체성분 쪽 오류·비활성이 운동 수신에 영향을 주지 않는다(반대도 동일)
- 초안은 bodylog 밖 별도 저장(`body-drafts`)에 산다 — 골격근 미입력 상태가 통계에
  0으로 오염되는 것을 구조적으로 차단. 확정 버튼은 골격근 없이 눌리지 않는다

## 단축어 레시피 (재조립용)

**단축어 "Body Plan 체성분 전송"** — 블록 2개 (⚠️ 기존 "Body Plan 전송"(운동)에 블록을
끼워 넣지 말 것 — 실패 격리 원칙, 별도 단축어):

1. **건강 지표 일괄 내보내기**(HAE):
   - 지표: **체중 · 체지방률 · 체질량** 3종만 (체질량=제지방체중 — 아래 확인법 참조)
   - 기간: `오늘` · **집계 없음/최소 단위**(개별 샘플) · 형식 `JSON` · 실행 시 보기 **끔**
2. **URL 콘텐츠 가져오기**:
   - URL: `https://daniel-tracker.vercel.app/api/body-import`
   - 메소드: `POST`
   - 헤더: 키 `X-Import-Token` / 값 ⟨IMPORT_TOKEN 48자 — 운동과 같은 값⟩
     — ⚠️ 엑셀 셀 복사 금지(보이지 않는 문자 오염, hae-setup.md 실증). 검증된 값에서 복사
   - 본문 요청: `파일` = **지표 내보내기** 결과 변수

**자동화 C (주력)**: 자동화 탭 → 앱 → **InBody** → **닫힐 때** → **즉시 실행** →
동작: Body Plan 체성분 전송. (순서 보장 트리거 — InBody 앱을 닫는 순간엔 건강 동기화가
이미 끝나 있다. 시간 트리거는 동기화 전 헛방 위험이 있어 쓰지 않는다)

**백업 등록**: 기존 21:30 백업 자동화(자동화 B)에 이 단축어를 **추가 동작**으로 등록.
같은 측정의 재전송은 서버가 무시(멱등)하므로 부작용 없음 — 트리거가 못 돈 날을 하루 안에 복구.

## 운영 수칙

- **아침 공복 1회 측정 고정** — 서버가 00:00~12:00(로컬) 밖 샘플을 초안에서 제외한다(B1).
  저녁에 재 보고 싶으면 봐도 되지만 앱 값은 아침 값이 유지된다
- **인바디 앱을 안 연 날은 자동화가 침묵** — 수동 입력이 폴백(기존 폼 그대로).
  수동으로 먼저 입력한 날 = 잠금 — 늦게 도착한 자동분은 조용히 폐기된다
- **초안은 골격근·점수를 입력해야 확정** — 확정 전에는 통계·공유 링크 어디에도 반영되지
  않는다(체중 포함). 아침에 InBody 앱에서 골격근·점수 보고 바로 입력하는 습관
- **"체질량=제지방" 확인법**: HAE 지표 선택 화면의 "체질량" 값이 애플 건강 앱의
  **제지방체중**과 일치하는지 1회 대조. 일치하면 그 지표가 맞다 (서버는 이름 키워드
  lean/제지방/체질량으로 매칭하며, "체질량지수(BMI)"는 자동 제외)
- 확정 후에도 히스토리에서 전체 편집·삭제 가능(잠금은 자동 갱신 차단이지 수동 편집 차단이
  아니다). 자동 수신 출신 레코드는 🧬 배지 + 편집 시 LBM 오타 가드(비율 0.53~0.61 밖 경고)
- iOS 메이저 업데이트 후 첫 측정 때 Body Plan 반영 확인 습관(hae-setup.md와 동일)

## 첫 실전송 확인 3종 (운영 첫 주 체크리스트 — 완료 시 이 문서 최종화)

설정 → 데이터 → "🧬 인바디 체성분 자동 수신" 카드의 수신 로그에서 확인:

- [ ] **⑴ 매칭 지표명 원본** — `수신 ...` 줄에 3개 지표명이 다 잡히는가.
      `미매칭 ...`에 예상 지표가 있으면 그 이름을 별칭으로 추가해야 한다(코드의
      `api/_lib/body-import-rules.js` 키워드 확장)
- [ ] **⑵ 체지방률 수신값 형** — `체지방형 18.7`(퍼센트형)인지 `체지방형 0.187`(소수형 →
      거부됨, B4 발동)인지. 소수형이면 ×100 변환을 별칭처럼 추가한다
- [ ] **⑶ 오늘 샘플 수** — `샘플1`(하루 1건 집계)인지 `샘플3`(개별, 재측정 포함)인지.
      개별이어야 재측정 시 최신 채택(B2)이 실측대로 동작한다

## 문제 해결

| 증상 | 원인/조치 |
|---|---|
| 측정했는데 초안이 안 뜸 | 앱 새로고침 → 설정 → 데이터 → 🧬 카드 수신 로그 확인 → 단축어 ▶ 수동 실행해 응답 메시지 확인. InBody 앱을 열었다 닫았는지(자동화 C 트리거) 확인 |
| "새 체성분 없음 · 아침 창 밖 N 제외" | 정상 — 12시 이후 측정은 초안 대상이 아님(B1). 아침 측정분은 이미 반영됐는지 확인 |
| "새 체성분 없음 · 중복 N 무시" | 정상 — 같은 측정의 재전송(21:30 백업 등)을 서버가 걸러낸 것 |
| "거부 N(소수형 의심...)" | 첫 실전송 확인 ⑵의 소수형 케이스 — 코드에 ×100 변환 추가 필요 |
| "거부 N(... 단위 ... 수용 불가)" | HAE 내보내기 단위가 kg/lb 외 — 로그의 단위 확인 후 변환 별칭 추가 |
| 401 토큰 불일치 | 헤더 키/값 확인 (키는 정확히 `X-Import-Token`, 값은 운동 단축어와 동일) |
| 503 | `IMPORT_BODY_CUTOVER_DATE` 미설정/형식 오류 — 아래 환경변수 확인 후 재배포. 운동 수신(503 아님)과 독립 |
| 미매칭에 지표명이 계속 남음 | 첫 실전송 확인 ⑴ — 그 이름을 매칭 키워드에 추가 |
| 초안이 사라짐 | 그 날짜를 이미 확정(또는 수동 입력)했는지 확인 — 잠금이 자동분을 폐기한 것(정상). 30일 지난 초안도 자동 정리됨 |

## 서버가 해주는 것 (몰라도 되지만 알면 안심)

- 아침 창(00~12시) 가드 · 같은 날 다중 샘플 최신 채택(8/5 재측정 3회 실증 반영) ·
  소수형(0~1) 체지방률 거부 · lb→kg 환산 · 범위 방어(체중 40~150·제지방 30~80·체지방률 3~60) ·
  컷오버 · 소스 관찰(InBody 외 소스는 필터) · 재전송/동시 도착 멱등 · 로그에 본문 전문 없음
- 규칙 단일 출처: `api/_lib/body-import-rules.js` (B1~B9) · 병합·잠금: `src/bodyDraft.js`

## 환경변수

| 변수 | 값 | 비고 |
|---|---|---|
| `IMPORT_TOKEN` | (기존 운동과 공용) | X-Import-Token 대조 |
| `IMPORT_UID` | (기존 운동과 공용) | 사서함 귀속 |
| `IMPORT_BODY_CUTOVER_DATE` | 예: `2026-08-08` (YYYY-MM-DD) | **신규.** 이 날짜 이전 측정 거부. 이 변수만 지우면 체성분 수신만 503으로 꺼진다(운동 무영향 롤백 스위치) |

## curl 실전 시뮬레이션 (Vercel 프리뷰 검증용 — Phase 3 기록)

프리뷰 URL(`$URL`)과 토큰(`$TOK`)을 넣고 4케이스 실행, 응답을 PR에 기록한다:

```bash
URL=https://<preview>.vercel.app/api/body-import; TOK=<IMPORT_TOKEN>
TODAY=$(date +%F)
# ① 정상 (아침 3종) → 200 {"accepted":1,...,"message":"체성분 초안 1건 접수"}
curl -sS -X POST "$URL" -H "X-Import-Token: $TOK" -H "Content-Type: application/json" -d '{"data":{"metrics":[
 {"name":"weight_body_mass","units":"kg","data":[{"date":"'$TODAY' 08:24:00 +0900","qty":73.6}]},
 {"name":"body_fat_percentage","units":"%","data":[{"date":"'$TODAY' 08:24:00 +0900","qty":18.7}]},
 {"name":"lean_body_mass","units":"kg","data":[{"date":"'$TODAY' 08:24:00 +0900","qty":60.5}]}]}}'
# ② 소수형 → 200 {"rejected":1,...,"message":"...소수형 의심..."}
curl -sS -X POST "$URL" -H "X-Import-Token: $TOK" -H "Content-Type: application/json" \
 -d '{"data":{"metrics":[{"name":"body_fat_percentage","units":"%","data":[{"date":"'$TODAY' 08:24:00 +0900","qty":0.187}]}]}}'
# ③ 아침 창 밖 → 200 {"excluded":1,...,"message":"...아침 창 밖 1 제외"}
curl -sS -X POST "$URL" -H "X-Import-Token: $TOK" -H "Content-Type: application/json" \
 -d '{"data":{"metrics":[{"name":"weight_body_mass","units":"kg","data":[{"date":"'$TODAY' 21:00:00 +0900","qty":74.9}]}]}}'
# ④ 토큰 오류 → 401 {"error":"unauthorized"}
curl -sS -X POST "$URL" -H "X-Import-Token: wrong" -H "Content-Type: application/json" -d '{"data":{"metrics":[]}}'
```
