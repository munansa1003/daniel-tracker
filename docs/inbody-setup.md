# 인바디 체성분 자동 수신 — 최종 구성 (클라우드 직수신 + HAE 폴백)

hae-setup.md(운동)의 자매 문서. 폰 교체·서버 재구축·단축어 파손 시 이 문서만으로 재조립할 수 있다.

**상태: 2026-08-07 실전 검증 완료.** 인바디 클라우드에서 5종(체중·체지방률·제지방·**골격근량·
인바디점수**)을 직접 수신해 자동 확정하는 것까지 실계정으로 확인했다. 타이핑 **0개**.

## 최종 아키텍처 — 2채널 + 수동 폴백

**주 채널(A): 인바디 클라우드 직수신 — 완전 무접촉, 5종 전부**

```
[아침 공복 H20 측정] → InBody 앱 열어 동기화(클라우드 저장)
  → Body Plan을 열면 서버(import-inbox)가 인바디 클라우드에서 직접 pull
  → 같은 검문소 규칙(B1~B9) 통과 → KV 사서함 → 앱 착지
  → 체중·체지방률·제지방·골격근량(SMM)·인바디점수(FS) 5종 실측 완비
  → LBM 비율 가드(0.53~0.61) 통과 시 자동 확정 — 입력 0개
  → 가드 보류 시에만 초안 카드에 수신값 표시 + 사용자 검토·확정
```

**폴백 채널(B): HAE 단축어 — 클라우드 장애·API 변경 시의 안전망 (3종)**

```
InBody 앱 닫힐 때(자동화 C) → 단축어 "Body Plan 체성분 전송"
  ① HAE 건강 지표 내보내기: 체중·체지방률·체질량(=제지방) · 오늘 · 분 단위 · JSON
  ② URL 콘텐츠 가져오기: POST /api/body-import
  → 같은 검문소·사서함 → 초안(골격근·점수는 카드에서 입력해 확정)
```

**최종 폴백**: 인바디 앱을 안 연 날은 두 채널 다 침묵 → 기존 수동 입력 폼 그대로.

- 두 채널은 **같은 검문·사서함·병합 규칙**을 쓴다 — 같은 측정이 양쪽으로 와도 필드별 최신
  채택으로 자연 통합(중복 없음). 클라우드가 정상일 땐 사실상 A만 일한다
- **운동 파이프라인과 완전 분리**: 별도 서버 경로·사서함/로그/seen 키. 상호 무영향
- 초안은 bodylog 밖 별도 저장(`body-drafts`) — muscle 미입력이 통계에 0으로 오염되는 것을
  구조적으로 차단. 자동 확정도 **실측 muscle이 있을 때만**(추정 기입은 여전히 금지)
- 비공식 API라 언제든 깨질 수 있음을 전제로 설계: 깨져도 B(HAE)+수동이 그대로 동작

## A채널 — 인바디 클라우드 직수신

### 검증된 프로토콜 (2026-08-07 실계정)

| 항목 | 값 |
|---|---|
| 지역 호스트 | `appapikrv3.lookinbody.com` (공통 `appapicommon.lookinbody.com`에서 KR 조회) |
| 로그인 | `POST /V2/Main/GetLoginWithSyncDataPartV2` — 전화번호 아이디 + 비밀번호 → JWT(24h) |
| 조회 | `POST /V2/InBody/GetInBodyData` (`UseInBodyHomeDevice: "true"` — **H20 가정용 포함**) |
| 확인된 기기·건수 | `EQUIP: H20N` · 474건 |
| 필드 매핑 | 체중 `BCA.WT` · 체지방률 `MFA.PBF` · 제지방 `BCA.FFM` · **골격근량 `MFA.SMM`** · **인바디점수 `WC.FS`** |

**점수는 `FS`다.** 응답에 `MScore`/`HScore`/`SScore`도 있지만 그건 앱 하단의 세부 점수(근육·
건강·슬림)이고, 사용자가 보는 대표 "인바디 점수"는 `FS`임을 같은 날 앱 표시값(82점)과 대조해 확정했다.

### ⚠️ Node의 `fetch`를 쓰지 말 것 (ID_BLOCK의 진짜 원인)

Node 전역 `fetch`(undici)는 요청에 **브라우저 지문 헤더**(`sec-fetch-mode: cors` ·
`accept-language: *` · `accept: */*`)를 자동 주입한다. 실제 앱(okhttp)도, 검증에 성공한
PowerShell도 이 헤더를 보내지 않는다. 인바디 서버는 이 차이를 보고 로그인을 `ID_BLOCK`으로
거절한다 — **IP 차단이 아니다**(IP 차단이면 HTTP 403이지, HTTP 200 + 앱 코드로 오지 않는다).

→ `api/_lib/inbody-cloud.js`의 `postJson`은 **`node:https.request`**를 쓴다. 우리가 준 헤더 +
Host/Content-Length만 전송해 성공한 요청과 동일한 형태를 유지한다. **이 부분을 fetch로
되돌리면 즉시 ID_BLOCK으로 회귀한다.**

부수 조치: `vercel.json`의 `regions: ["icn1"]`(서울) — 한국 계정이 미국 데이터센터에서
로그인하는 지역 불일치도 함께 제거(덤으로 국내 응답 지연 감소).

### 계정 잠금 방어 (반드시 유지)

인바디는 **로그인 실패가 반복되면 계정을 잠근다.** 실측에서 `PW_FAIL_4 → PW_FAIL_3 →
PW_FAIL_2`로 **남은 시도 횟수가 카운트다운**되는 것을 확인했다(2회 남기고 중단).

그래서 `api/import-inbox.js`는:
- **인증 실패(`PW_FAIL`·`ID_BLOCK`·로그인 실패)는 단 1회로 크리덴셜을 24시간 봉인** —
  자동은 물론 "지금 확인"(force)도 차단. 재시도로 낫지 않는 오류이기 때문
- 봉인은 **크리덴셜 지문**(sha256 앞 16자)에 묶여 있어 **env에서 비밀번호를 고치면 즉시 해제**
  (24시간 기다릴 필요 없음)
- 일시적 오류(5xx·네트워크)는 상한 3회까지 재시도 허용
- 성공하면 봉인·실패 카운터 모두 리셋

**인바디 앱에서 정상 로그인 1회 = 인바디 쪽 실패 카운터 리셋**(실측 확인). 잠금이 걱정되면 이 방법.

### 1. 환경변수 (Vercel → Settings → Environment Variables)

| 변수 | 값 | 비고 |
|---|---|---|
| `IMPORT_TOKEN` | (운동과 공용) | X-Import-Token 대조 |
| `IMPORT_UID` | (운동과 공용) | 사서함 귀속 + 클라우드 pull 주인 판별 |
| `IMPORT_BODY_CUTOVER_DATE` | 예 `2026-08-07` | 이 날짜 이전 측정 거부. 지우면 체성분 수신 전체가 꺼짐 |
| `INBODY_LOGIN_ID` | 인바디 앱 아이디(전화번호 **숫자만**, 앞자리 0 포함) | 클라우드 직수신용 · Sensitive |
| `INBODY_LOGIN_PW` | 인바디 앱 비밀번호 | 클라우드 직수신용 · Sensitive. **이 둘만 지우면 클라우드만 꺼진다**(HAE·운동 무영향 롤백 스위치) |
| `INBODY_COUNTRY` | 기본 `KR` | 지역 서버 자동 라우팅(ISO 코드) |

⚠️ **환경변수는 "새 배포"부터 적용된다.** 추가·수정 후 반드시 **Deployments → 맨 위
Production → ⋯ → Redeploy**. 이 순서를 빠뜨리는 것이 가장 흔한 실패 원인이었다.

⚠️ **비밀번호는 직접 타이핑할 것.** 붙여넣기 과정에서 특수문자가 잘려 11자 비밀번호가 8자로
저장된 사고가 실제로 있었다(그게 `PW_FAIL`의 원인이었다). 저장 후 아래 진단으로 길이를 확인한다.

⚠️ 기존 "Body Plan 전송"(운동)에 블록을 끼워 넣지 말 것 — 실패 격리 원칙, **별도 단축어**.

### 수신 로그 줄 읽는 법

```
08-07 14:16  클라우드  샘플1 +1 중복0 거부20 창밖0
```

## 문제 해결

| 증상 | 원인/조치 |
|---|---|
| **버튼을 눌러도 아무 반응 없음** | 상태 한 줄을 볼 것(위 표). 미설정·봉인·스로틀 중 하나다 |
| `ID_BLOCK` | 서버가 `fetch`로 요청했을 때 발생 — `node:https.request`인지 확인(위 ⚠️ 절) |
| `PW_FAIL_N` | 비밀번호 불일치. **N은 남은 시도 횟수(카운트다운)** — 연타 금지. 로그의 `PW N자`로 길이 확인 후 Vercel에서 수정 → 재배포 |
| 🔒 잠금이 안 풀림 | 비밀번호를 **실제로 바꿔야** 지문이 달라져 해제된다. 같은 값 재저장은 무효 |
| `PW 0자` | 환경변수가 배포에 미적용 → **재배포** |
| `ID 10자(101…)` | 전화번호 **앞자리 0 누락** |
| 클라우드 줄이 아예 안 생김 | `INBODY_LOGIN_ID`·`PW` 미설정(서버가 조용히 건너뜀) → 추가 후 재배포 |
| 초안이 사라짐 | 그 날짜를 이미 확정(또는 수동 입력)했는지 확인 — 잠금이 자동분을 폐기한 것(정상). 30일 지난 초안도 자동 정리 |
| 자동 확정 안 되고 카드에 경고 | LBM 비율 가드 보류(수신 골격근이 평소 비율 밖) — 정상 동작. 값 확인 후 수동 확정 |
| 단축어 400 "지표 페이로드가 아님" | 본문 요청이 `JSON`으로 돼 있음 → **`파일`**로 변경 |
| 401 토큰 불일치 | 헤더 키/값 확인 (키는 정확히 `X-Import-Token`) |
| 503 | `IMPORT_BODY_CUTOVER_DATE` 미설정/형식 오류 → 확인 후 재배포. 운동 수신과 독립 |
| 클라우드가 계속 실패 | 인바디 API 변경 가능성(비공식). **HAE 단축어·수동 입력은 그대로 동작하니 서비스는 무중단** — 코드 수리 요청 |

범위 방어(체중 40~150 · 제지방 30~80 · 체지방률 3~60) · 컷오버 · 소스 관찰(InBody 외 필터) ·
부분 수신 허용 · 재전송/동시 도착 멱등 · 로그에 본문 전문 없음

규칙 단일 출처 `api/_lib/body-import-rules.js` · 클라우드 클라이언트 `api/_lib/inbody-cloud.js` ·
사서함 기입 `api/_lib/body-inbox-store.js` · 병합·잠금·자동 확정 `src/bodyDraft.js`

## curl 시뮬레이션 (B채널 검문소 점검용)

```bash
URL=https://daniel-tracker.vercel.app/api/body-import; TOK=<IMPORT_TOKEN>
TODAY=$(date +%F)
# ① 정상 → 200 "체성분 초안 1건 접수"   ② 소수형 → "소수형 의심"
# ③ 21:00 → "아침 창 밖 1 제외"          ④ 토큰 오류 → 401
curl -sS -X POST "$URL" -H "X-Import-Token: $TOK" -H "Content-Type: application/json" -d '{"data":{"metrics":[
 {"name":"weight_body_mass","units":"kg","data":[{"date":"'"$TODAY"' 08:24:00 +0900","qty":73.6}]},
 {"name":"body_fat_percentage","units":"%","data":[{"date":"'"$TODAY"' 08:24:00 +0900","qty":18.7}]},
 {"name":"lean_body_mass","units":"kg","data":[{"date":"'"$TODAY"' 08:24:00 +0900","qty":60.5}]}]}}'
```
