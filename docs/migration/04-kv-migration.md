## 1. 무엇을 옮기는가 — 키 목록과 유실 시 피해

`api/_lib/kv.js`를 통해 쓰는 키 전부다 [코드]. **타입은 쓰는 명령에서 나온다**(HSET=hash, LPUSH=list, SADD=set, 나머지 SET=string).

| 키 | 타입 | TTL | 쓰는 곳 | 유실되면 |
|---|---|---|---|---|
| `import:seen:<uid>:<importKey>` | string | **영구** | `health-import.js:131` (`SET … NX`) | 같은 기록을 **다시 받아들인다**(아래 주석 — 정상 경로에서는 이중 계상까지 가지 않는다) |
| `import:body-seen:<uid>:<key>` | string | **영구** | `body-inbox-store.js:17` (`SET … NX`) | 같은 측정을 다시 받아들인다(확정 잠금·묘비가 2차 방어) |
| `import:inbox:<uid>` | hash | 영구 | `health-import.js:130` | 아직 앱이 받아가지 않은 **운동 수신분 소실**(도장만 남으면 영영 못 받는다 — §4) |
| `import:body-inbox:<uid>` | hash | 영구 | `body-inbox-store.js:16` | 아직 받아가지 않은 **체성분 수신분 소실** |
| `import:log:<uid>` | list(20) | 영구 | `health-import.js:142` (`LPUSH`+`LTRIM 0 19`) | 설정 화면의 수신 로그만 비어 보임(데이터 손실 아님) |
| `import:body-log:<uid>` | list(20) | 영구 | `body-inbox-store.js:29·40` | 위와 같음 |
| `import:body-cloud-at:<uid>` | string | 영구(값이 시각) | `import-inbox.js:125` | 인바디 30분 스로틀 창이 초기화 — 다음 열람 때 한 번 더 당겨온다(무해) |
| `import:body-cloud-fail:<uid>` · `-authblock:` · `-ok:` | string | 영구 | `import-inbox.js:141·156·162` | 연속 실패 카운터·인증 봉인 해제 → 계정 잠금 방어가 한 판 느슨해진다 |
| `import:body-cloud-lock:<uid>` | string | **60초**(`SET … NX EX`, `CLOUD_LOCK_TTL_SEC` `import-inbox.js:47`) | `import-inbox.js:116` | 없음 — **그래서 기본 제외한다**(옮기면 새 DB가 최대 1분간 잠긴 채 시작한다) |
| `push:uids` | **set** | 영구 | `push-sync.js:67` (`SADD`) | **리마인더 중단** — 크론이 대상 목록을 잃는다 |
| `push:sub:<uid>` | string | 영구 | `push-sync.js:66` | **리마인더 중단**(재구독은 사용자 제스처 필요 — DR-9) |
| `push:state:<uid>` | string | 영구 | `push-sync.js:85` | 알림 설정·마지막 발송 시각 초기화 → 하루 중복 발송 가능 |
| `share:<token>` | string | **최대 7일**(`SET … EX`) | `share-store.js:34·55` | **공유 링크 즉사**(revoke 도장도 함께 사라짐) |
| `share:hits:<token>` | string | 7일 | `share-store.js:69` (`INCR`) | 조회수만 0으로 |
| `rl:<라우트>:<ip>` | string | 60초(`security.js:78`) | `security.js:67` (`INCR`+`EXPIRE`) | 없음 — **그래서 기본 제외한다** |

> **도장 유실 = 이중 계상, 이라고 03의 DR-14는 적었지만 실제로는 한 겹 더 있다.**
> 도장을 잃으면 단축어가 보낸 같은 기록이 사서함에 **다시 들어온다**. 그 다음을 앱이 막는다:
> `mergeImports`가 그 날짜에 같은 `importKey`가 이미 있으면 반영하지 않고 ack만 하고 버린다
> (`src/importMerge.js:67` [코드]). 그래서 **정상 경로에서는 이중 계상까지 가지 않는다**.
> 다만 그 2차 방어선은 **날짜 문서에 `importKey`가 남아 있을 때만** 동작한다(백업 복원·수동 편집으로
> 지워졌다면 뚫린다). 도장을 반드시 옮겨야 하는 이유는 여전하지만, 피해 크기는 이 정도로 적는 게 정확하다.

스크립트는 `string`·`hash`·`set`·`list`·`zset` 다섯 타입을 모두 복원한다.
현재 코드가 만드는 것은 앞의 넷뿐이지만, 앞으로 늘어날 자리를 미리 막아 둔 것이다.
모르는 타입(stream 등)이 나오면 **조용히 넘기지 않고** 미지원으로 세어 종료 코드 2로 끝낸다.

### 복사 순서는 안전 순서다

키를 아무 순서로나 옮기면 안 된다. **중간에 끊겼을 때 어느 쪽으로 남느냐**가 달라지기 때문이다.
스크립트는 두 쌍의 순서를 코드로 못 박는다(`COPY_LAST`, 테스트로 고정):

| 먼저 | 나중에 | 거꾸로 하면 |
|---|---|---|
| `import:inbox:*` · `import:body-inbox:*` (사서함) | `import:seen:*` · `import:body-seen:*` (도장) | 도장만 넘어가면 그 수신분은 **영영 못 받는다** — 도장이 재수신을 막는다. 반대 순서의 최악은 "중복 한 번"이고 그건 되돌릴 수 있다 |
| `push:sub:*` (구독) | `push:uids` (발송 대상 목록) | 목록에 uid가 있는데 구독이 없으면 **첫 크론이 그 uid를 목록에서 지운다**(`cron-reminders.js:76`) — 복구하려면 사용자가 브라우저에서 알림 권한을 다시 눌러야 한다(DR-9) |

앱이 쓸 때도 같은 비대칭을 지킨다(`health-import.js:130-131`: HSET → `SET … NX`) [코드].
이 스크립트는 그 논리를 이관에 그대로 옮겼을 뿐이다.

**순서만으로는 부족하다.** 앞엣것이 실패했는데 뒤엣것을 계속 쓰면 결국 같은 상태가 된다.
그래서 스크립트는 앞 묶음(사서함·구독)을 **전부 끝낸 뒤에** 뒤 묶음(도장·목록)을 보내고,
앞에서 **실패나 미지원 타입이 하나라도 나오면 뒤는 아예 보내지 않는다**(`보류 N개`로 보고, 종료 코드 2).
원인을 고쳐 다시 돌리면 보류분이 마저 간다(멱등).

## 2. 준비 [사람]

1. **Upstash 직접 계정으로 로그인** — Vercel Marketplace 경유가 아니라 `console.upstash.com` 자체 계정.
   (Vercel 통합으로 만든 DB는 Vercel이 소유권을 쥔다. 그게 DR-14의 위험 자체다)
2. **Redis DB 생성.** 이름은 무엇이든 좋다(예: `daniel-tracker-kv`).
   - 리전: **서울(`ap-northeast-2`)이 목록에 있으면 서울**, 없으면 **도쿄(`ap-northeast-1`)** [사람 · 콘솔 목록 확인].
     함수가 `asia-northeast3`(서울)에 뜨므로(01 §3) 가까울수록 왕복이 짧다.
   - **Eviction은 끈다**(기본 꺼짐). 켜져 있으면 메모리가 차는 순간 `import:seen`(영구 도장)이 조용히 날아갈 수 있다.
   - 무료 티어로 충분하다 — 현 데이터는 §1 기준 수백 KB 규모다(②의 "용량(근사)"로 실측하라).
3. **REST 자격증명 복사** — 콘솔의 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`.
4. **옛 DB의 자격증명 확보** — Vercel 프로젝트 → Settings → Environment Variables의
   `KV_REST_API_URL`·`KV_REST_API_TOKEN`(통합이 자동 주입한 값).

> **읽기 전용 토큰을 쓰지 않는다.** Upstash 콘솔은 토큰을 "Standard"와 "Read Only" 둘로 준다.
> 안전해 보인다고 원본에 Read Only 토큰을 쓰면 **`SCAN`이 거부된다**("Some powerful read commands
> (e.g. SCAN, KEYS) are also restricted with read only token" [스니펫]). 양쪽 다 Standard 토큰을 쓰고,
> 원본을 건드리지 않는 보장은 **스크립트의 명령 화이트리스트**에 맡긴다(§8 D-9 — 테스트로 고정).
> 실제로 이 실수를 하면 `HTTP 400`과 함께 서버가 준 문구가 그대로 찍히므로 원인을 바로 알 수 있다.

### 실행 장소

**Google Cloud Shell** 또는 **로컬 PC** 둘 중 하나. 어느 쪽이든 원칙은 같다:

- 토큰은 **셸 환경변수로만** 준다. 명령줄 인자로 주면 셸 히스토리와 프로세스 목록(`ps`)에 남는다.
- 토큰을 파일(`.env` 등)에 적어 저장소에 두지 않는다. 저장소에는 이 문서와 스크립트만 있다.
- Cloud Shell을 쓸 때: 세션이 끊기면 env가 사라진다. 긴 작업이 아니므로(수 초~수 분) 문제되지 않는다.
- 스크립트는 **의존성이 없다**. `npm install` 없이 Node 20+ 만 있으면 된다(`fetch`·`AbortSignal.timeout` 내장).
  Cloud Shell의 Node는 `node --version`으로 20 이상인지만 확인한다.

```bash
# 저장소를 받아서
git clone https://github.com/munansa1003/daniel-tracker.git && cd daniel-tracker

# 토큰을 셸에만 넣는다 (history에 남기기 싫으면 앞에 공백 한 칸 — HISTCONTROL=ignorespace)
export SRC_URL='https://<옛DB>.upstash.io'
export SRC_TOKEN='<옛 토큰>'
export DST_URL='https://<새DB>.upstash.io'
export DST_TOKEN='<새 토큰>'
```

Windows PowerShell(로컬 PC)이라면:

```powershell
$env:SRC_URL='https://<옛DB>.upstash.io'; $env:SRC_TOKEN='<옛 토큰>'
$env:DST_URL='https://<새DB>.upstash.io'; $env:DST_TOKEN='<새 토큰>'
node scripts/kv-migrate.mjs
```

`--match` 같은 옵션에 `*`를 넣을 때 PowerShell은 따옴표가 필요 없지만, bash에서는
`--match='push:*'`처럼 **반드시 따옴표로 감싼다**(안 감싸면 셸이 파일 이름으로 펼친다).

## 3. 실행 절차

### ② 점검 (dry-run) — 아무것도 쓰지 않는다

```bash
node scripts/kv-migrate.mjs
```

접두사별 키 수, TTL 분포, 용량(문자열 값 바이트 합계 + 컬렉션 원소 수), 그리고 대상 DB가 비어 있는지를 보고한다.

- **`DST_URL`/`DST_TOKEN` 없이도 돈다** — 새 DB를 만들기 전에 "무엇을 옮기게 되는지" 먼저 재보라고 그렇게 두었다.
- 여기서 §1 표에 없는 접두사가 나오면 `(분류 없음)`으로 찍힌다. **그건 멈추고 확인할 신호다**(다른 서비스와 DB를 공유하고 있다는 뜻일 수 있다).
- 기본 제외(`rl:*` · `import:body-cloud-lock:*`)는 세지 않고 "제외 N개"로만 보고한다.

### ③ 복사

```bash
node scripts/kv-migrate.mjs --apply
```

- SCAN으로 원본을 훑고(커서 순회, `COUNT 200`), 키마다 `TYPE`·`PTTL`을 읽어 타입별로 복원한다.
- **TTL은 남은 시간으로 옮긴다**(`SET … PX` / 컬렉션은 `PEXPIRE`). 영구(`-1`)는 영구 그대로.
- **대상이 비어 있지 않으면 거부한다.** 재실행이라 의도한 것이면 `--allow-nonempty`를 붙인다(멱등이므로 안전).
- 원본에는 **쓰기 명령을 하나도 보내지 않는다** — 읽기 명령 화이트리스트로 코드가 막는다.
- 중간에 끊겨도 그냥 다시 돌리면 된다: 이미 같은 값·TTL인 키는 건너뛴다.

기대 출력:

```
복사 N개 · 건너뜀(이미 같음) 0개 · 사라짐 0개 · 실패 0개 · 미지원 타입 0개
복사 완료. 이어서 --verify 로 대조하세요.
```

문자열 키는 복사 직전에 **원본의 `STRLEN`(바이트 수)과 실제로 읽어온 값의 바이트 수**를 맞춰 본다.
어긋나면 그 키는 **쓰지 않고** 실패로 보고한다(§8 D-13). Upstash REST가 유효하지 않은 UTF-8을
`�`로 조용히 바꿔 돌려주기 때문인데, 이 앱은 JSON 문자열만 저장하므로 정상 상황에서는 걸리지 않는다.

`실패`나 `미지원 타입`이 0이 아니면 종료 코드 2로 끝난다. **그 상태로 ⑤로 넘어가지 않는다.**
그 경우 도장·구독자 목록은 `보류 N개`로 보고되고 **아예 쓰이지 않는다**(§1 "복사 순서는 안전 순서다").

또 셋을 더 막는다:

- **옮길 키가 0개면 중단한다**(종료 코드 2). 주소·토큰·`--match` 오타가 "복사 완료"로 보이는 것이
  이 도구에서 가장 알아채기 어려운 실패다. 정말 비어 있는 것이 맞다면 `--allow-empty`.
- **`--allow-nonempty`로 덮어쓸 때, 대상에만 있는 키 수를 경고한다.** 컷오버 이후의 재실행이면
  그 키들이 새 DB의 최신 값이라는 뜻이므로 §4를 먼저 읽어야 한다(스크립트가 지우지는 않는다).
- **켜기/끄기 플래그에 값을 붙이면 거부한다.** `--allow-nonempty=no`가 값만 무시된 채 플래그를
  켜서 **안전장치를 끄려다 켜는** 일이 없게 한다. `--exclude=`(빈 값)도 마찬가지로 거부한다 —
  제외 목록이 조용히 비면 `rl:*`와 60초 락까지 새 DB로 따라간다.

### ④ 대조

```bash
node scripts/kv-migrate.mjs --verify
```

- **건수**: 원본·대상 전체 키 수와 **접두사별** 수를 나란히 찍는다.
- **표본 100개**: 정렬한 키 목록에서 균등 간격으로 뽑아(무작위가 아니라 **재실행해도 같은 표본**)
  타입·값·TTL·**바이트 길이(STRLEN)** 까지 비교한다. 바이트 길이를 함께 보는 이유는 §8 D-13.
- 하나라도 어긋나면 어긋난 키를 찍고 종료 코드 2.

`--apply --verify`로 한 번에 돌려도 된다(복사가 성공했을 때만 대조로 넘어간다).

### ⑤ Vercel 환경변수 교체·재배포 [사람]

1. Vercel → 프로젝트 → **Settings → Environment Variables**
2. `KV_REST_API_URL`·`KV_REST_API_TOKEN`을 **새 DB 값으로 바꾼다**(Production·Preview 모두).
3. **재배포**한다(Deployments → 최신 배포 → Redeploy). env 변경은 재배포해야 함수에 반영된다.

> **함정 [사람 확인]**: 이 두 변수는 Marketplace 통합이 자동 주입한 것이라 프로젝트 화면에서
> 통합 소유로 표시될 수 있다. 값이 편집되지 않으면 **통합이 주입한 변수만 제거하고 같은 이름의
> 일반 변수를 새로 추가**한다. **통합 자체를 연결 해제하지는 않는다** — 그게 DB 삭제 위험(DR-14)이다.
> 코드는 `KV_REST_API_*`를 먼저 읽고 없을 때만 `UPSTASH_REDIS_REST_*`를 읽으므로(`kv.js:12-13`,
> `security.js:57-58` [코드]), `UPSTASH_*`만 추가하는 우회는 **효과가 없다**. 반드시 `KV_REST_API_*`가 새 값이어야 한다.

### ⑥ 앱에서 확인 [사람]

재배포 직후, 다음 셋을 **순서대로** 확인한다. 하나라도 이상하면 §6으로.

| 확인 | 방법 | 정상 |
|---|---|---|
| 자동 수신 카드 | 단축어로 운동 1건 전송 → 앱 열기 | 홈의 수신 카드에 뜨고, **한 번만** 반영된다(이중 계상 없음) |
| 공유 링크 | 이관 **전에 만들어 둔** 링크를 연다 | 그대로 열린다(TTL이 남아 있는 동안) |
| 푸시 | `node scripts/kv-migrate.mjs --verify --match='push:*' --exclude='push:state:'` — 옛↔새를 **양쪽 다** 보고 종료 코드로 판정한다. 또는 Upstash 콘솔에서 **새 DB**에 `push:sub:<uid>`와 `push:uids`가 있는지 직접 본다 | `대조 통과`, 종료 코드 0 |

특히 **첫 번째가 핵심**이다. 도장(`import:seen`)이 제대로 넘어왔다면 **이관 전에 이미 받은 기록을
다시 보내도 사서함에 다시 뜨지 않는다** — 그걸 직접 시험해 보는 게 가장 확실한 검증이다.

> **푸시는 "앱에서 정상으로 보이는 것"으로 판정하면 안 된다.** 브라우저에는 구독이 그대로 남아
> 있으므로 앱은 멀쩡해 보이는데 **서버 쪽 구독만 없을 수 있다**. 그 상태는 스스로 낫지 않는다:
> 구독을 서버로 올리는 경로는 `enablePush`(사용자 제스처) 하나뿐이고, 주기적으로 도는
> `syncPushState`는 상태만 보내고 구독은 보내지 않는다(`src/push.js:54-64` [코드]).
> DR-9의 "알림 다시 켜기" 배너도 `!getSubscription()` 조건이라 **뜨지 않는다**.
> 그래서 반드시 **DB를 직접 확인**하고, 없으면 설정에서 알림을 **껐다가 다시 켠다**.
>
> **점검(dry-run)으로 확인하면 안 된다.** `node scripts/kv-migrate.mjs --match='push:*'`은 `SRC`(= **옛 DB**)만
> 훑는다. 새 DB가 텅 비어 있어도 옛 DB의 `push:*`가 그대로 "있음"으로 찍혀 **거짓 안심**을 준다.
> 반드시 `--verify`를 쓴다(원본과 대상을 함께 읽고 불일치면 종료 코드 2).
> `push:state:`를 제외하는 이유: 재배포 뒤 앱을 한 번만 열어도 새 DB의 `push:state`가 갱신돼(`push-sync.js:85`)
> 옛 값과 정당하게 달라진다. 확인해야 할 것은 구독(`push:sub:*`)과 발송 대상 목록(`push:uids`)이다.

### ⑦ Firebase 시크릿은 처음부터 새 값 [사람]

Firebase 함수에 `KV_REST_API_TOKEN`을 등록할 때(01 §5, DR-7 A+a) **새 DB의 토큰**을 넣는다.
옛 토큰은 어디에도 등록하지 않는다 — 컷오버 이후 두 원점이 서로 다른 DB를 보는 사고를 원천 차단한다.
`KV_REST_API_URL`은 시크릿이 아니라 일반 params로 두되 값은 **새 DB의 URL**.

## 4. 드리프트 — ④와 ⑤ 사이의 창

복사(③)가 끝난 뒤에도 **⑤의 재배포가 끝나기 전까지 Vercel 배포는 여전히 옛 DB에 쓴다.**
그 창에서 들어온 쓰기는 새 DB에 없다. 그리고 **그 창을 나중에 통째로 다시 복사해 메우면 안 된다** —
재복사는 컷오버 이후 새 DB에 쌓인 최신 값을 옛 값으로 덮어쓰기 때문이다(사서함·푸시 구독이 특히 위험).

그래서 이 이관은 **"조용한 창"에서 한다**:

1. **시간대를 고른다.** 자동 쓰기는 둘뿐이다 — 리마인더 크론(매일 **20:00 KST**, `vercel.json` [코드])과
   앱을 열 때 도는 사서함 pull(`import-inbox`). **20시 근처를 피하고**, 작업 중에는 앱을 열지 않는다.
2. **단축어를 돌리지 않는다.** 애플워치 운동 전송·인바디 수신이 창 안에서 일어나지 않게 한다.
3. **③→④→⑤를 이어서 한다.** 실제 소요는 수 초 + 재배포 1~2분이다.
4. **⑤의 env를 바꾸기 직전에 `--verify`를 한 번 더 돌린다**:

   ```bash
   node scripts/kv-migrate.mjs --verify --sample=1000   # 표본을 키 수만큼 키운다
   ```

   여기서 통과하면 ③~지금 사이에 드리프트가 없다는 뜻이다. 그대로 ⑤로 넘어간다.

   **키 수 비교로 판정하지 않는다.** 창 안의 쓰기 상당수는 **키 수를 바꾸지 않는다** —
   revoke는 같은 `share:<token>`에 묘비를 덮어쓰고(`share-store.js:55` [코드]), 알림 설정 변경은
   기존 `push:state:<uid>`를 덮어쓰며(`push-sync.js:85` [코드]), 사서함 ack는 해시의 **필드만** 지운다
   (`import-inbox.js` HDEL). 셋 다 키 수는 그대로다. 값을 봐야 보인다.

   재배포(⑤)를 **지난 뒤에는** 이 대조가 더 이상 깨끗하게 나오지 않는다 — 새 DB에 정상 쓰기가
   쌓이기 때문이다. 그때 나오는 불일치는 "드리프트 목록"이 아니라 "창 안 드리프트 + 컷오버 후
   정상 쓰기"가 섞인 것이므로, 키 이름으로 갈라서 본다.

   대조가 불일치를 내면 **키 종류별로** 처리한다:

   드리프트에는 **두 방향**이 있다. 창 안의 **쓰기**는 옛 DB에 남아 새 DB에 없고(유실),
   창 안의 **삭제·소비**(사서함 ack, 공유 링크 revoke)는 새 DB에 반영되지 않아 **되살아난다**.

   | 드리프트한 키 | 처리 |
   |---|---|
   | `import:seen:*` · `import:body-seen:*` (도장) | 값이 불변이라 덮어써도 안전하다: `node scripts/kv-migrate.mjs --apply --allow-nonempty --match='import:seen:*'` (체성분은 `--match='import:body-seen:*'`) |
   | `import:inbox:*` · `import:body-inbox:*` (사서함) | **자동 복사 금지.** 옛 DB의 해당 해시를 눈으로 보고(콘솔), 빠진 항목이 있으면 **단축어로 다시 보낸다**. 도장이 이미 넘어갔다면 먼저 그 도장 키를 새 DB에서 지운 뒤 다시 보내야 들어간다. (반대로 창 안에서 ack된 항목이 새 DB에 되살아나 있어도 무해하다 — 앱이 `importKey`로 걸러 ack만 하고 버린다, `importMerge.js:67`) |
   | `push:*` | **자동 복사 금지 · 가장 조용한 사고.** 창 안에서 알림을 새로 켰다면 새 DB에 구독이 없고, 그러면 **밤 8시 알림이 영영 오지 않는데 오류도 배너도 없다**(위 ⑥의 경고). 반드시 DB에서 `push:sub:<uid>`·`push:uids`를 눈으로 확인하고, 없으면 앱에서 알림을 껐다 켠다(DR-9) |
   | `share:*` (되살아나는 쪽) | **자동 복사 금지.** 창 안에서 **revoke한 링크가 새 DB에서는 살아 있을 수 있다** — 폐기한 링크가 다시 열린다는 뜻이다. 창 안에 revoke한 적이 있으면 새 DB에서 그 링크를 **다시 폐기**한다(앱의 공유 관리에서 revoke 한 번). 링크가 안 열리는 반대 경우는 새로 만들면 된다(최대 7일짜리라 곧 만료된다) |
   | `import:log:*` · `import:body-log:*` · `rl:*` · 인바디 스로틀 키 | 무시해도 된다(표시용·일시적) |

> 왜 사서함을 자동으로 안 옮기는가: 사서함은 해시고, 스크립트는 컬렉션을 `DEL` 후 재생성한다(§8 D-3).
> 컷오버 이후 새 DB에 들어온 수신분이 있는데 옛 사서함을 덮어쓰면 **그 수신분이 사라진다**.
> 이 한 줄이 이 문서에서 가장 값비싼 문장이다.

## 5. 옛 DB는 언제 지우는가

**병행 기간(DR-8, 14일)이 끝나고 Vercel 프로젝트를 정리할 때까지 지우지 않는다**(02 C4).
그때 순서는:

1. 새 DB에서 ⑥의 세 확인이 14일 내내 정상이었는지 본다.
2. Vercel 프로젝트를 삭제한다 — 이 시점에 통합이 사라지며 **옛 DB가 함께 사라져도 무방하다**(이미 옮겼으므로).
3. 만약 옛 DB가 남으면(직접 계정으로 이전되었다면) 수동으로 지운다. 남겨 두면 요금이 아니라 **혼동**이 비용이다.

## 6. 되돌리기

**되돌리기는 데이터가 아니라 env를 되돌리는 것이다.** 옛 DB는 이 절차에서 단 한 바이트도 바뀌지 않았다
(스크립트가 원본에 쓰기 명령을 보내지 못하게 코드로 막았고, 테스트가 그걸 고정한다).

| 상황 | 조치 |
|---|---|
| ⑤ 재배포 후 앱이 이상하다 | Vercel env를 **옛 값으로 되돌리고 재배포**. 즉시 원상복구된다 |
| ③이 중간에 실패했다 | 그냥 `--apply --allow-nonempty`로 다시 돌린다(멱등) |
| ④가 불일치를 잡았다 | 불일치 키를 보고 원인을 고친 뒤 `--apply --allow-nonempty` → `--verify` |
| 새 DB를 잘못 만들었다(리전 등) | 새 DB를 하나 더 만들고 `DST_*`만 바꿔 ③부터 다시. 옛 DB는 그대로다 |

되돌린 뒤 새 DB에 쌓인 데이터가 있다면(⑤~되돌리기 사이의 쓰기) §4의 표와 같은 방식으로 판단한다.

## 7. 이 스크립트가 하지 않는 것 (한계)

| 한계 | 왜 / 걸리면 어떻게 |
|---|---|
| **바이너리(비UTF-8) 값을 옮기지 못한다** | REST가 JSON 문자열로 주고받는 구조라 원형 보존이 불가능하다. 다만 **조용히 상하지는 않는다** — 복사 직전 바이트 수 대조로 잡아내 그 키를 건너뛰고 실패로 보고한다(§8 D-13). 이 앱은 JSON 문자열만 저장하므로 해당 없음 |
| **컬렉션 하나가 10MB를 넘으면 실패한다** | `HGETALL`/`SMEMBERS`를 한 번에 읽기 때문. 요청 상한(Free/PAYG 10MB)을 넘으면 REST가 거부한다 — **에러로 드러나고 종료 코드 2**이므로 조용한 손실은 아니다. 현 데이터는 로그 리스트 20개 상한·공유 본문 600KB 상한이라 해당 없다(`import:inbox:*`만 상한이 없다). 걸리면 그 키만 콘솔에서 손으로 옮긴다 |
| **컬렉션 복사가 중간에 실패하면 그 키가 대상에서 지워진 채 남을 수 있다** | 컬렉션은 `DEL` 후 재생성하므로(§8 D-3), `DEL`은 됐는데 뒤의 `HSET`이 실패하면 그 키가 비어 버린다. **실패로 보고되고**(종료 코드 2), `--apply --allow-nonempty`로 재실행하면 복구된다 — ④ 대조를 통과하기 전에는 ⑤로 넘어가지 않는 이유다 |
| **원자적 스냅숏이 아니다** | 키 단위로 읽고 쓰므로 "복사 도중에 들어온 쓰기"는 일부만 반영될 수 있다. 그래서 §4의 조용한 창에서 돌린다. 순서(§1)와 멱등성이 이 비원자성의 피해를 "되돌릴 수 있는 쪽"으로 몰아 준다 |
| **점검(dry-run)은 값을 읽지 않는다** | 키 수·타입·TTL·크기만 본다(싸게 끝내려고). 값 무결성 확인은 `--apply`와 `--verify`에서 한다 |
| **대상의 여분 키를 지우지 않는다** | 대조에서 "원본에 없는 대상 키 N개"로 알리기만 한다. 이관 도구가 대상을 지우기 시작하면 사고 반경이 너무 커진다 |

## 8. 결정 (이 세션에서 확정)

| # | 결정 | 왜 |
|---|---|---|
| D-1 | 점검(dry-run)은 `DST_*` 없이도 돈다 | ①(새 DB 생성)보다 먼저 "무엇을 옮기는가"를 재보는 게 순서상 자연스럽다 |
| D-2 | `rl:*`와 `import:body-cloud-lock:*`는 기본 제외 | 둘 다 60초 안에 스스로 사라지는 값이다. 락은 옮기면 **새 DB가 최대 1분간 잠긴 채 시작**한다. `--exclude`로 목록을 갈아끼울 수 있다(그러면 기본값은 사라진다 — 출력에 늘 제외 접두사를 찍는 이유) |
| D-3 | 컬렉션은 `DEL` 후 재생성 | 대상에 남아 있던 필드·원소와 섞이면 **에러 없이 값만 틀린다**(가장 나쁜 실패 방식) |
| D-4 | 리스트는 `LRANGE 0 -1` 순서 그대로 `RPUSH` | `LPUSH`로 복원하면 수신 로그가 **뒤집힌다**(최신이 맨 아래로). 테스트로 고정 |
| D-5 | TTL은 **남은 시간**(`PX`/`PEXPIRE`)으로 이관 | 절대시각을 옮길 수단이 REST에 없다. 복사 지연만큼(초 단위) 짧아지는 것은 허용 |
| D-6 | 멱등 판정의 TTL 허용오차 300초 | 값이 같아도 TTL은 복사 지연만큼 차이 난다. 이걸 불일치로 보면 재실행 때마다 전부 다시 쓴다 |
| D-7 | 대상이 비어 있지 않으면 `--apply` 거부(기본) | "엉뚱한 DB에 쏟는" 사고를 한 번 막는다. 재실행은 `--allow-nonempty`로 명시 |
| D-8 | 대조 표본은 무작위가 아니라 정렬 후 균등 간격 | 같은 입력이면 같은 표본 — "다시 돌렸더니 통과"가 안 생긴다 |
| D-9 | 원본 읽기 전용을 **명령 화이트리스트**로 강제 | 주석은 코드를 막지 못한다. 실수로 쓰기 명령을 넣으면 즉시 던진다 |
| D-10 | 드리프트는 재복사가 아니라 "조용한 창 + 점검"으로 다룬다 | 통짜 재복사는 컷오버 이후 새 DB의 최신 값을 덮는다(§4) |
| D-11 | 파이프라인은 **500커맨드/4MB**로 끊고, 길이가 아니라 **바이트**로 센다 (`PIPE_MAX_CMDS`·`PIPE_MAX_BYTES` — `kv-migrate.mjs:40`·`:43`) | 요청 본문 상한은 Free/PAYG **10MB**라 절반 아래로 잡는다. 한글은 문자 수와 바이트 수가 3배까지 벌어져 `.length`로 세면 상한을 넘길 수 있다. 커맨드 수 상한은 문서에 없어 공식 클라이언트가 쓰는 1000보다 보수적으로 500. 공유 링크 본문이 최대 600KB(`share-store.js:18` [코드]) — 한 커맨드가 혼자 상한을 넘으면 단독 전송 |
| D-12 | 실행은 Cloud Shell 또는 로컬, 토큰은 셸 env로만 | 인자로 주면 히스토리·`ps`에 남는다. 스크립트는 토큰을 출력하지 않는다(테스트로 고정) |
| D-13 | 값은 UTF-8 문자열로 다룬다(바이너리 미지원) | REST가 JSON 문자열로 주고받으므로 비UTF-8 값은 왕복에서 상한다. 앱은 JSON 문자열만 저장하므로 해당 없음 — 그래도 표본 대조에서 **STRLEN(바이트 길이)** 을 함께 봐서 상했으면 잡는다 |
| D-14 | 의존성 0(Node 내장 `fetch`) | Cloud Shell에서 `npm install` 없이 즉시 실행. 이관 도구가 자기 의존성 때문에 못 도는 일이 없게 |
| D-15 | 복사 순서를 코드로 고정(사서함→도장, 구독→목록) | §1의 "복사 순서는 안전 순서다". 우연히 사전순으로 맞는 게 아니라 `COPY_LAST`로 못 박고 테스트로 지킨다 |
| D-16 | 파이프라인은 **왕복 수**를 줄이는 것이지 커맨드 한도를 아끼는 게 아니다 | 지시문의 전제를 실측 문서로 정정한다: Upstash는 "one command = one billable request"이고 `/pipeline`에 N개를 담으면 **N개로 과금·계수**된다 [스니펫]. 그래도 파이프라인을 쓰는 이유는 왕복 지연(수백 회 → 수 회)이다. 참고로 요청 하나의 본문 상한은 Free/PAYG **10MB**라서 4MB에서 끊고, 커맨드 수 상한은 문서에 없어 공식 클라이언트가 쓰는 1000보다 보수적인 500으로 잡았다 [스니펫] |
