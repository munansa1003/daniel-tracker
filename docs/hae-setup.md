# 애플워치 운동 자동 기록 — 최종 구성 (HAE Basic + 단축어)

2026-08-06 확정·실전 검증 완료. 폰 교체·단축어 파손 시 이 문서만으로 재조립할 수 있다.

## 최종 아키텍처

```
[워치에서 운동 종료]
  → iOS 자동화 트리거 (Apple Watch 운동 · 종료될 때 · 즉시 실행)
  → 단축어 "Body Plan 전송"
      ① 대기 15초                          (워치→건강 앱 데이터 도착 대기)
      ② HAE 운동 내보내기: 오늘 · v2 · JSON  (실행 시 보기 끔)
      ③ URL 콘텐츠 가져오기: POST            (아래 상세)
  → 검문소 /api/health-import (화이트리스트·컷오버·insert-only dedup)
  → KV 사서함 → Body Plan 앱 열 때 병합 → 유효목표 자동 반영
```

- **HAE 플랜: Basic ₩4,400 1회성** (2026-08-06 구매, 평생) — 단축어 동작·수동 내보내기 포함
- 앱 내 REST API 자동화(1시간 주기)는 **프리미엄 전용이라 사용하지 않음** — 체험 기간
  검증용으로만 썼고, 단축어 경로가 더 빠르다(종료 즉시 vs 최대 1시간)
- HAE의 "수동 내보내기" 화면(CSV·30일·지표 등)은 이 파이프라인과 무관 — 설정 불필요

## 단축어 레시피 (재조립용)

**단축어 "Body Plan 전송"** — 블록 3개:

1. **대기**: 15초
2. **운동 내보내기**(HAE): 기간 `오늘` · 버전 `v2` · 형식 `JSON` · 실행 시 보기 **끔**
3. **URL 콘텐츠 가져오기**:
   - URL: `https://daniel-tracker.vercel.app/api/health-import`
   - 메소드: `POST`
   - 헤더: 키 `X-Import-Token` / 값 ⟨IMPORT_TOKEN 48자⟩
     — ⚠️ 엑셀 셀 복사 금지(보이지 않는 문자 오염으로 "네트워크 연결 유실" 발생, 2026-08-06 실증).
     HAE 자동화 화면의 검증된 값에서 전체 선택·복사하거나 수기 입력
   - 본문 요청: `파일` = **운동 내보내기** 결과 변수

**자동화 A (주력)**: 자동화 탭 → Apple Watch 운동 → 운동 종류 `아무거나` · **종료될 때만** →
**즉시 실행** → 동작: Body Plan 전송. (검증 기간엔 "실행되면 알리기" 켜두면 동작 확인에 좋다)

**자동화 B (백업, 권장)**: 특정 시간 · 매일 21:30 → 즉시 실행 → Body Plan 전송.
트리거가 어쩌다 못 돈 날을 하루 안에 복구한다 — 중복은 서버가 무시하므로 부작용 없음.

## 운영 수칙

- **화이트리스트 종목은 워치로만 기록** — 러닝·사이클링·걷기·축구·계단 오르기·하이킹·수영·
  스트레칭(워치 '식히기' 유형)·근력. 같은 운동을 앱에 또 수동 입력하면 이중 계상
- **근력**: 워치에서 "기능성 근력 훈련"으로 기록 → 앱에 **"근력 운동" 한 건**으로 저장 →
  세부 종목(벤치프레스 3×10 등)은 그 기록을 눌러 **메모**에 기입
- **워치 없이 한 운동만** 앱에 수동 입력 (예: 워치 안 차고 탄 자전거)
- 새 유형을 쓰면 응답·수신 로그에 "대상 외 N 제외"와 유형명이 남는다 → 화이트리스트 확장 요청
- **iOS 메이저 업데이트 후 첫 운동 때 Body Plan 반영을 확인**하는 습관 (단축어 동작이
  일시적으로 깨질 수 있는 유일한 현실적 리스크 — 보통 HAE 업데이트로 복구)

## 문제 해결

| 증상 | 원인/조치 |
|---|---|
| 운동했는데 앱에 안 뜸 | Body Plan 새로고침 → 설정 → 데이터 → 자동 가져오기 카드의 수신 로그 마지막 시각 확인 → 단축어 ▶ 수동 실행해 오류 여부 확인 |
| "네트워크 연결이 유실되었습니다" | 헤더 값 오염(보이지 않는 문자) — 토큰을 깨끗한 출처에서 재입력 |
| 401 토큰 불일치 | 헤더 키/값 오타·공백 확인 (키는 정확히 `X-Import-Token`) |
| 503 | 서버 환경변수 3종(IMPORT_TOKEN·IMPORT_UID·IMPORT_CUTOVER_DATE)·재배포 확인 |
| 400 파싱/형식 오류 | 운동 내보내기 형식이 JSON인지, 본문 요청이 `파일`인지 확인 |
| "0건 추가 · 중복 N 무시" | 정상 — 이미 저장된 운동의 재전송을 서버가 걸러낸 것 (insert-only 설계) |

## 서버가 해주는 것 (몰라도 되지만 알면 안심)

- **형식 자동 인식**: HAE `{ data: { workouts: [...] } }`·표준 봉투 모두 수용 (workouts v1/v2),
  단축어 파일 첨부(비JSON Content-Type)의 문자열/버퍼 본문도 직접 파싱
- **시간대 보정**: UTC(`… Z`)로 와도 귀속일은 한국시간 벽시계 기준 (기본 +09:00,
  env `IMPORT_TZ_OFFSET`로 변경 가능)
- **단위 방어**: duration 초→분, 에너지 kJ→kcal 환산, kcal 반올림
- **빈 전송 정상 처리**: 새 운동 없으면 200 "0건 추가"
- 화이트리스트(한/영 별칭) · 컷오버 · insert-only · race 원자성 · 사서함 → 앱 병합 →
  유효목표 자동 반영 — 규칙 단일 출처는 `api/_lib/import-rules.js`
